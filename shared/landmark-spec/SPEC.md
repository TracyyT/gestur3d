# Landmark spec v0

The single definition of how hand landmarks are represented and normalized in Gestur3D. The browser (TypeScript) and training code (Python) both implement it, and **both must reproduce `golden/v0.json`** exactly (within 1e-5). That's the guard against train/serve skew: if preprocessing drifts between Python and the browser, accuracy drops without any error.

## 1. Raw landmarks

| Property   | Convention                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| Source     | MediaPipe Hand Landmarker, 21 landmarks per hand                                                         |
| Frame      | **Raw, unmirrored** camera frame. Only the on-screen preview is mirrored.                                |
| `x`, `y`   | Normalized to [0, 1] of frame width / height, origin top-left, y down                                    |
| `z`        | Depth relative to the wrist, roughly the same scale as `x`; smaller = closer to camera                   |
| Handedness | The user's own hand (`Right` = user's right hand). Valid because input is unmirrored. Never swap labels. |
| Layout     | Flat `Float32Array(63)`: `[x0, y0, z0, x1, y1, z1, …]`, landmark order as MediaPipe                      |

Landmark indices: 0 wrist; 1–4 thumb (CMC → tip); 5–8 index (MCP → tip); 9–12 middle; 13–16 ring; 17–20 pinky.

## 2. Normalization (`normalizeHand`)

Inputs: raw landmarks, handedness, frame aspect ratio (width / height), options.

1. **Aspect correction.** Multiply `x` and `z` by `aspect`, so all axes are in units of frame height and distances are isotropic.
2. **Translate.** Subtract the wrist (landmark 0) from every point. The wrist becomes the origin.
3. **Canonical hand.** If `mirrorLeft` (default `true`) and the hand is `Left`, negate `x`. Every hand then looks like a right hand, so one model serves both.
4. **Scale.** Divide by the **palm size**: the 2D (x, y) distance from the wrist to the middle-finger MCP (landmark 9), measured after step 3. If palm size < 1e-6, normalization fails (returns `null`). The 2D distance is used because `z` is noisy.
5. **Rotation (optional).** If `alignRotation` (default `false`), rotate in the x–y plane so the wrist→middle-MCP vector points straight up (0, −1). This is **off by default**: in-plane orientation separates gestures like thumbs-up from thumbs-down. M5 compares both settings and reports the result.
6. **Output.** Flat `Float32Array(63)`.

## 3. Versioning

Any change to the steps above is a new version (`v1`, …) with its own golden file. Exported models record the spec version they were trained with, and the browser refuses to run a model whose spec version it doesn't implement.

## 4. Golden vectors

`golden/v0.json` holds input cases and expected outputs, generated by the reference TypeScript implementation (`pnpm --filter @gestur3d/landmark-spec golden`). Their job is **cross-language parity**: the Python port must match them. Correctness of the reference itself is covered by independent property tests (translation, scale and mirror invariance) and a hand-computed case in `src/normalize.test.ts`.
